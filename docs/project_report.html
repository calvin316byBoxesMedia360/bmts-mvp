BMTS - Reporte de Proyecto

BoxesMedia360 / Beto's Mobile & Truck Services / Version documental 0.1 / 2026-05-25

Resumen

El proyecto BMTS busca convertir el conocimiento operativo del taller en un sistema digital simple, confiable y escalable. La primera etapa debe enfocarse en flotas, historial vehicular, prevencion de duplicados, ordenes de trabajo e invoice basico.

Prioridad confirmada: partida de nacimiento del vehiculo con vPIC/NHTSA, foto principal obligatoria guardada localmente, QR unico imprimible, historial vivo, prevencion de duplicados, piloto Community Tree Service y version web-first.

Hallazgos

  • El mayor riesgo operativo es repetir servicios o no cobrar a tiempo.
  • La primera version debe capturar el proceso real antes de automatizarlo demasiado.
  • El sistema debe separar informacion interna de informacion visible para cliente.
  • Los agentes de IA seran mas utiles despues de tener datos consistentes.
  • El ZIP de habilidades confirma soporte para producto, Next.js, React Native, seguridad, accesibilidad y ejecucion por planes.
  • QuickBooks queda fuera del MVP inicial, pero debe contemplarse en el modelo para integracion futura.
  • SmogCheck sera la primera regla fuerte: advertir y bloquear si se intenta antes de la fecha permitida de 3 meses, con autorizacion de admin para excepciones.
  • La foto del vehiculo sera obligatoria durante el alta de la partida de nacimiento y se almacenara localmente en el MVP.
  • Cada vehiculo tendra un QR unico vinculado a la base local para abrir ficha, historial y carga de servicio mediante escaneo.
  • El MVP local ya fue abierto exitosamente en `http://localhost:4173/` y se guardo captura para Remotion.
  • La consulta vPIC/NHTSA por VIN ya esta conectada y autollenando datos tecnicos ampliados en la partida de nacimiento.
  • Se agrego pegado, normalizacion, validacion y foto local del VIN para reducir errores de captura.
  • PaddleOCR fue aceptado como OCR provisional open source para leer VIN desde foto; Google Vision queda como alternativa futura.
  • PaddleOCR quedo instalado localmente y el endpoint OCR ya leyo correctamente un VIN sintetico completo; el flujo mantiene confirmacion humana antes de consultar vPIC.
  • Se resolvió un problema de permisos denegados en la caché de PaddleOCR (`.paddlex_runtime`) para el usuario de Windows.
  • Se implementó el escalado automático con `Pillow` para fotos tomadas con móviles (ej. 4000x1848), reduciendo el tamaño a un máximo de 1500px, habilitando la precisión del OCR local al 100% en fotos de campo.
  • Se automatizó el flujo en la interfaz web de forma que al leer un VIN por OCR o al pegarlo, se ejecuta la decodificación de vPIC/NHTSA inmediatamente en un solo paso si el código tiene 17 caracteres.
